# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Docker (primary workflow)
```bash
make up          # Build and start all services (MongoDB + app)
make down        # Stop all services
make logs        # Follow container logs
make clean       # Stop and remove volumes (destructive — deletes data)
```

### Local development (requires MongoDB running separately)
```bash
make mongo       # Start only MongoDB in Docker
make dev         # Build frontend, embed it, run Go server locally
make dev-frontend  # Run Vite dev server standalone (hot reload, proxies to backend)
```

### Backend
```bash
# From backend/
go vet ./...
go test ./... -race -count=1
go test ./path/to/package -run TestName -race  # run a single test

# Backend requires the frontend dist to exist before build/run
mkdir -p backend/cmd/server/dist && echo '<!doctype html>' > backend/cmd/server/dist/index.html
```

### Frontend
```bash
# From frontend/
npm ci
npm run build        # tsc + vite build
npm run lint         # eslint
npx tsc --noEmit     # type check only
```

### Chrome extension
```bash
make chrome-extension   # Build socialpod-capture.zip for Chrome Web Store upload
```

## Architecture

### Single-binary deployment
The React frontend is built and copied into `backend/cmd/server/dist/`, then embedded at compile time via `//go:embed dist/*` in `frontend.go`. The Go binary serves both the REST API (`/api/*`) and the SPA (all other routes fall back to `index.html`). A single port (default 8080) handles everything.

The build sequence: `npm run build` → `cp -r frontend/dist backend/cmd/server/dist` → `go build`.

### Backend (`backend/`)
Go module `socialmedia`, using Gin as the HTTP framework.

- `cmd/server/main.go` — wires all dependencies; defines four route groups: public `/api`, authenticated `/api` (JWT/API-token required), admin-only `/api/admin`, team-admin `/api/team`
- `internal/config/` — loads all config from environment variables
- `internal/database/mongo.go` — `MongoDB` wrapper that exposes typed collection accessors (`Posts()`, `Users()`, `Teams()`, etc.) and creates indexes on startup
- `internal/models/` — BSON-tagged Go structs for each MongoDB collection (`post.go`, `user.go`, `team.go`, `social_account.go`, `footer.go`, `mention.go`, `convention.go`, `upload.go`, `watermark.go` (the former collection, read only to migrate it), `team_invite.go`, `publisher_handle.go`, `news_draft.go`, `episode_draft.go`, `oauth.go`, `growth.go`, `media.go`, `image_draft.go`, `agent.go`, `backup.go`, `upload_token.go`)
- `internal/handlers/` — one file per handler group (`media.go` + `media_watermarks.go`, `auth.go`, `posts.go`, `admin.go`, `inbox.go`, `footers.go`, `convention.go`, `mentions.go`, `invite.go`, `bgg.go`, `news.go`, `episode.go`, `publisher_handles.go`, `mcp.go`, `mcp_growth.go`, `oauth.go`, `capture.go`, `growth.go`, `growth_stats.go`, `growth_ai.go`, `media.go`, `caption_check.go`, `transcribe.go`, `agents.go` (+ `agent_runner.go`, `agent_schedule.go`), `system_backup.go`, `post_designs.go`, `uploads_once.go`; the MCP agent tools in `mcp_agent.go`, `mcp_images.go`, `mcp_sources.go`, `mcp_capture.go`, `mcp_rest.go`)
- `internal/middleware/auth.go` — `AuthRequired` tries three token types in order: JWT → user API token (`sm_...`) → team API token (`st_...`); sets `userId`, `isAdmin`, `isTeamAdmin`, `teamId` on the Gin context. The same bearer token authenticates both REST API and MCP requests. `MCPAuthRequired` guards `/api/mcp`: it additionally accepts OAuth access tokens (`spa_...`, `middleware/oauth.go`) and drops admin flags.
- `internal/services/` — platform-specific: `bluesky.go`, `instagram.go`, `instagram_insights.go`, `twitter.go`, `mastodon.go`, `threads.go`, `linkedin.go`, `youtube.go`; infrastructure: `scheduler.go`, `growth_jobs.go`, `imageutil.go`, `fonts.go`, `compose.go`, `email.go`

The scheduler (`services/Scheduler`) runs every 30 seconds, queries for posts where `status == "scheduled"` and `scheduledAt <= now`, and publishes them. Footers are fetched from the DB and appended at publish time (not stored on the post itself).

Convention queues have their own 30-second background loop (`ConventionHandler.StartAutoPoster` in `handlers/convention.go`). Approved queue items are a *set*, not pre-scheduled: whenever a queue is active and inside its date window and its `nextPostAt` is due, the loop picks one approved item at random, creates a `scheduled` post for it (which the shared scheduler then publishes), marks the item consumed, and rolls `nextPostAt` forward by the schedule gap. `POST /convention/queues/:id/schedule` is a manual "post one random item now" trigger.

Photos reach a queue three ways: one item per photo (`POST …/items`), one carousel item from many (`POST …/items/gallery`, an item with `imageUrls`; the UI calls these carousels), or the queue's **gallery** (`handlers/convention_gallery.go`, collection `convention_gallery`, `models.ConventionGalleryPhoto`, `Convention/GallerySection.tsx`): photos waiting for a decision. `GET /convention/queues/:id` returns them as `gallery`; `POST /convention/queues/:id/gallery` (multipart `images`) adds, `DELETE …/gallery/:pid` deletes and frees the file, and `POST …/gallery/move {photoIds, target: single|carousel, itemId?}` moves photos out in the order given: a pending single-post item each, or all into a new carousel item, or appended to an unscheduled one (`itemId`; a plain item becomes a carousel starting with its image, `appendCarouselImages`). The move takes the photos out of the gallery first, so a racing second move finds them gone, and puts them back if creating the items fails; the image URLs pass to the items unchanged. An item with any `imageUrls` shows as a carousel even with one image, so it can be added to. Deleting the queue deletes its gallery.

A carousel item's pages are edited on its card (`convention_carousel.go`) until it is scheduled: the strip under the picture (`SortableTiles`) drags them into order, removes one, and its + buttons before the first and after the last page add a front or back page, uploaded or made in the image editor on a blank 1080×1080 canvas. `POST /convention/queues/:id/items/:iid/images` (multipart `image`, optional `index`, default the end) adds one; `PUT …/images {imageUrls}` sets the order, taking only the item's own images (`droppedImages`) and freeing those left out.

A queue's watermark (`watermarkId`) is composited onto each image by `postItem` at post time, never stored on the item. The queue page's crop button (next to the edit pencil on each item card) therefore opens the shared `ImageCropper` with `bakeWatermark={false}`: the overlay is drawn over the crop area so the framing can be judged, but the uploaded crop is clean, or the overlay would be stamped twice. Crop and edit both act on the gallery image currently shown; `PUT /convention/queues/:id/items/:iid/image` takes an `index` form field for that, keeps `imageUrl` mirroring `imageUrls[0]`, refuses scheduled items, and frees the replaced upload.

**Quick Reel** (`handlers/convention_reel.go`, `Convention/QuickReel.tsx`, `ImageEditor/quickReel.ts`) turns a clip into an Instagram reel in a minute, for the convention floor. A queue's `reelTemplateId` (the queue form's "Quick Reel template": media library video templates only) names the template; the queue page's Quick Reel button opens a dialog that goes pick → upload (a temporary upload, `uploadTempWithProgress`, with a progress bar) → lead in/out and a few words of hints → render and caption in parallel → review → publish. `renderQuickReel` instantiates the template like the editor (library fonts loaded under the editor's family names), puts the clip into the template's largest clip layer, else its largest image layer if that covers at least a third of the canvas (a smaller one is a logo or decoration), cover-cropped by `srcCrop` (`clipTarget`), else under everything full-frame, and exports with the editor's own `renderVideo`. The clip's kept part sets the reel's length (3–180 s), not the template: `renderVideo`'s `hold` runs the template's layers, effects and other clips over the template's own length and holds its last frame from there, while the clip's layer (`hold.playOn`) plays the whole reel; the template's music plays on. The one edit to the reel is where it cuts into the clip and out of it: `ClipTrimmer` (`Convention/ClipTrimmer.tsx`) plays the picked file locally, with a filmstrip decoded by mediabunny and two handles (the window between them drags both; arrow keys, Shift for 1 s) kept 3–180 s apart, and `renderQuickReel`'s `trim` becomes the clip's `trimStart` and the reel's length. Otherwise the reel is only previewed; the caption is editable. `POST /api/convention/queues/:id/reel/caption {hints}` writes it with the team's "Rewrite for Instagram" prompt (`DefaultInstagramRewritePrompt` otherwise) plus the game-title quoting rule and the queue's hashtags; `POST /api/convention/queues/:id/reel` (multipart `video`, `caption`, `uploadedAt`) stores the MP4 and creates a scheduled Instagram reel (`origin: quick-reel`, the queue's Instagram account and footer) at `quickReelTime`: 30 minutes after the clip's upload, or now once that has passed. The review step's "Save as draft" sends `draft=true` instead: the same post with `status: draft` (caption optional and unchecked, `scheduledAt` still the suggested time), to finish in the PostEditor. `quick-reel` drafts are a person's, so the agent draft queue (`loadDraftQueue`, `checkDraftCap`) leaves them out. The dialog releases the temporary clip when it closes or the page is left (`pagehide`); closing it mid-upload cancels the upload while the body is still going out, and releases the clip once the server answers if it was already all sent (`uploadWithProgress`'s `signal`). The rendered MP4 belongs to the post, so deleting the post frees it, and a failed publish frees it at once. What slips through anyway (no connection) the hourly temporary-upload cleanup frees a day later.

### AI requests (`handlers/ai_prompt.go`)
Every AI call (all go to OpenRouter's chat completions) builds its `messages` with `chatMessages(system, user)`, which appends `noDashRule` to the system prompt: the em dash is banned in all generated text, whatever prompt an admin or team configured. A new AI call must use `chatMessages` too; `TestEveryAIRequestUsesChatMessages` fails otherwise. Keep em dashes out of the built-in prompt texts as well, since they prime the model to use them.

### Instagram growth (`handlers/growth*.go`, `services/growth_jobs.go`)
Tools for growing an Instagram account against a follower goal. The Instagram login asks for `instagram_business_manage_insights` (`instagramAuthURL` in `admin.go`); accounts connected before that need a reconnect for Insights.

- **Follower snapshots** — the scheduler's growth loop (hourly, separate from the 30-second publishing loop) upserts one `follower_snapshots` document per Instagram account and UTC day (`followers_count` needs only `instagram_business_basic`).
- **Post Insights** — the same loop reads reach, views, shares, saves, likes, comments, follows and profile visits for Instagram posts published in the last 60 days and stores them on the post's Instagram result (`results.$.insights`), more often while a post is young. Instagram rejects a whole request when one metric does not apply to the media type, so feed posts, reels and stories ask for different sets (`instagram_insights.go`). A failed read keeps the old numbers and records the error.
- **Team settings** — `Team.Growth` (`models/growth.go`): the follower goal (target, start/end, optional start-count override, halfway review date + threshold, default midway and 40%), the weekly plan (recurring slots: weekday 0 = Monday, optional `HH:MM`, format reel/carousel/image/story/any, label), the single-image warning limit, the "Rewrite for Instagram" prompt and the agent draft cap. `GET /api/growth/settings` (any member), `PUT /api/team/growth` (team admin; frontend page `/admin/growth`).
- **Growth page** (`/growth`, `GET /api/growth/instagram?accountId=&start=&end=`) — goal tracker (`computeGoalProgress`: weekly net vs. required, halfway status `pending`/`ok`/`below`), the weekly report for the week the client sends (`buildWeeklyReport`: top 3 by shares + saves, per-format sends/saves per reach, weakest format) and ad candidates (`markAdCandidates`: reels and carousels of the last 30 days in the top 20% by shares + saves). `POST /api/growth/refresh` re-reads followers and the last 30 days of Insights; `POST /api/posts/:id/insights` one post. The pure computations live in `growth_stats.go` and are unit-tested.
- **Dashboard AI insights** append `instagramPerformanceSummary` (real numbers, goal progress) to the posting summary.
- **Calendar** — open weekly-plan slots render as dashed placeholders on today and future days (clicking one opens the editor at the slot's time and type), and each week gets a format-mix line with a warning above the single-image limit (`services/instagramGrowth.ts`). Both hide while a calendar filter is on. The calendar shows ISO week numbers (the ones the goal tracker uses): a `W<n>` tag on each Monday of the month grid, and in the title of the week and 3-day views.
- **PostEditor** — Instagram collaborators (max 3, pre-filled from the BGG publishers' Instagram handles, `publisherInstagramHandles`) and image tags (the @mentions of the Instagram caption, editable) are stored as `collaborators` / `userTags` on the post and sent as `collaborators` / `user_tags` when the container is created; tags go on a carousel's first image. Instagram refuses the whole container for an unknown username, so `createContainerWithExtras` retries without them and the result carries a `warning`. A reel has a cover (`coverUrl`, an upload, or `thumbOffset`, a frame in ms; sent as `cover_url`/`thumb_offset` by `reelCoverParams`, never dropped on that retry): the "Choose cover" row under the reel's video opens `ReelCoverPicker`, which scrubs to a frame ("Use this frame"), or opens the image editor on that frame or on a picked image and uploads the result as the cover; "Let Instagram pick" clears both. A new video drops a picked frame; `coverUrl` is in `uploadReferences` and freed with the post. `create_post`/`update_post` over MCP take both (an empty `coverUrl` or `thumbOffset: -1` clears). A caption checker (hook, closing question, share prompt, 3–5 hashtags, a tagged account, not identical to the Bluesky text) and "Rewrite for Instagram" (`POST /api/growth/rewrite-instagram`, team prompt or `DefaultInstagramRewritePrompt`) sit under the Instagram text. Published posts show their Insights. The News and Episode forms show the same caption checker under their Instagram text; its "Rewrite for Instagram" button appears only with "Customize per platform" on, beside the Instagram label, and writes the Instagram override (from the Bluesky text when that is empty) — there is no Bluesky counterpart, the Bluesky text being the short one written first.

### MCP server (`handlers/mcp.go`)
An MCP (Model Context Protocol) server is available at `POST /api/mcp` using the Streamable HTTP transport. It exposes all user-level operations as MCP tools: posts CRUD, footers, mentions, watermarks, accounts, profile, news drafts, and episode drafts. Authentication uses the same bearer token (`sm_...`) as the REST API — one token works for both interfaces.

MCP clients (Claude Code, OpenCode, etc.) configure the server URL and an `Authorization: Bearer <token>` header — or sign in with OAuth instead (below).

The MCP endpoint has its own middleware, `middleware.MCPAuthRequired`, not `AuthRequired`. It accepts JWTs, API tokens and OAuth access tokens, and **always clears `isAdmin`/`isTeamAdmin`**: MCP exposes user features only, even for an admin (`get_profile` reports both as false). Never add an admin or team-admin tool to it. An unauthenticated request gets a 401 with `WWW-Authenticate: Bearer resource_metadata="…"`, which is how OAuth clients discover the authorization server.

#### OAuth / OpenID Connect (`handlers/oauth.go`)
Remote MCP clients that can't take a pasted token — Claude.ai custom connectors (and the Claude desktop/mobile apps, which share them), ChatGPT connectors, Claude Code's `/mcp` sign-in — use the built-in OAuth 2.1 authorization server, following the MCP authorization spec:

- Discovery: `/.well-known/oauth-protected-resource` (RFC 9728), `/.well-known/oauth-authorization-server` (RFC 8414) and `/.well-known/openid-configuration`, each also under the `/api/mcp` path suffix. The issuer is `APP_URL`, which must therefore be the public HTTPS URL for Claude.ai or ChatGPT to connect — their servers make the calls.
- Dynamic client registration at `POST /api/oauth/register` (RFC 7591). Redirect URIs must be https, http on loopback (any port matches, RFC 8252), or a native app's private-use scheme.
- Authorization code + mandatory PKCE S256. The authorization endpoint is the SPA page `/oauth/authorize` (`OAuthConsentPage`): it sends a signed-out user through `/login?next=…`, then calls `GET /api/oauth/authorize` to validate the request and `POST /api/oauth/authorize` to approve or deny, and follows the returned `redirectUrl`. An unknown client or unregistered redirect URI is shown as an error and never redirected to.
- `POST /api/oauth/token` (authorization_code, refresh_token with rotation), `POST /api/oauth/revoke`, `GET /api/oauth/userinfo`, `GET /api/oauth/jwks`. With the `openid` scope the token response carries an RS256 ID token; the signing key is generated on first use and stored in `oauth_keys`.
- Tokens are opaque (`spa_` access, 1 h; `spr_` refresh, 90 days), stored only as SHA-256 hashes in `oauth_tokens`, with codes in `oauth_codes`; TTL indexes expire both. **OAuth access tokens are accepted by `/api/mcp` and userinfo only** — `AuthRequired` does not know them, so the REST API rejects them.
- The Profile page lists connected apps (`GET /api/oauth/grants`) and disconnects one (`DELETE /api/oauth/grants/:clientId`, deletes all its tokens). Regenerating the API token does not affect OAuth connections. The MCP handler implements the JSON-RPC 2.0 protocol with `initialize`, `ping`, `tools/list`, and `tools/call` methods. Each tool performs the same database queries as the corresponding REST handler, respecting team/user scoping.

MCP growth tools (`mcp_growth.go`): `get_post_insights` (one post, or every Instagram post of the last N days, with sends/saves per reach and the ad-candidate flag; `refresh` reads Instagram first) and `get_account_insights` (followers, goal tracker, weekly report and account totals for a range). `create_post`/`update_post` take `collaborators` and `userTags`, and for a reel `coverUrl`/`thumbOffset`.

MCP draft tools: `create_news_draft`, `list_news_drafts`, `get_news_draft`, `update_news_draft`, `delete_news_draft`, `post_news_draft`, `create_episode_draft`, `list_episode_drafts`, `get_episode_draft`, `update_episode_draft`, `delete_episode_draft`, `post_episode_draft`. Post drafts (post/story/reel) are regular posts created with `status: "draft"` via `create_post`.

#### Content agent tools
The MCP server also carries what an agent needs to fill the draft queue on its own (user-level only, like every MCP tool; `TestAgentToolsStayUserLevel` guards that). A tool that exposes an existing endpoint runs that REST handler through `callREST` (`mcp_rest.go`) with the caller's context keys, so it behaves exactly like the endpoint; don't reimplement a handler for MCP.

- **Planning** (`mcp_agent.go`): `get_growth_settings` (the growth settings, read-only), `get_open_slots` (weekly-plan slots of the next N days no Instagram post fills, matched like the calendar's `openSlotsForDay`, in a `timezone`, default Europe/Berlin; each with an RFC3339 `at` for `scheduledAt`).
- **Content**: `import_bgg` (runs `BGGHandler.FetchGame`, stores the cover as an upload instead of returning base64, `overlay` picks the team overlay; `createDraft` creates a post draft with text, hashtags and the publishers as collaborators), `upload_from_url` (runs `UploadFromURL`), `capture_url` (`mcp_capture.go`, runs `CaptureHandler.Capture`; without the extension's page images a non-BGG news/post capture fetches the article image with `fetchArticleImage`).
- **Images** (`mcp_images.go`): `list_watermarks` (description, size, the team `roles` each serves, `fullCanvas` for frame overlays; `preview` attaches thumbnails), `update_watermark`, `list_media`/`add_media`/`update_media`/`delete_media` (`kind` image/video/font/color/template/watermark filters the list; `add_media`/`update_media` take `color` for a colour entry, `update_media` `watermark` to mark or unmark an image), `get_image` (size plus a preview; for a library font, a text sample set in it, `previewImage`), `compose_image` (`services/compose.go`: base by `url`/`mediaId`/`watermarkId` fitted cover/contain/blur to a format, filter presets and adjustments, then image/text/rect/gradient layers placed by anchor or x/y in canvas fractions; text in the built-in fonts or a media library font (`fontMediaId`); stored as an upload, max 2160 px a side); or from a media library template (`template: {mediaId, layers}`, `mcp_templates.go` + `services/compose_template.go`): the editor design drawn server-side on its own canvas size (scaled down past 2160 px), with per-layer changes by index (`text`, `fontScale`, `color`; an image swapped by `url`/`mediaId`/`watermarkId` and cover-cropped into the layer's frame, `focusX`/`focusY`; `hide`). A replaced text keeps its alignment point and vertical centre. The renderer mirrors the Konva stage in `editorModel.ts` (image and shape layers by centre, texts by top-left, line height 1.15, outline/shadow/corners/borders; dashed/dotted borders are drawn solid, glow as a soft ring, system fonts fall back to the Go fonts; shapes and brush strokes in `compose_paint.go`, a feather as a Gaussian of sigma feather/2 like the canvas shadow; a layer's `blend` is drawn on its own and blended onto what is below with the W3C formulas in `compose_blend.go`), so keep it in step with `imageLayerParts`/`shapeLayerParts`/`paintStrokeAttrs`/`textLayerAttrs`. `list_media` lists a template's layers as `templateLayers` (index, kind, text/src, shape and fill, box in canvas fractions) instead of the raw JSON; `color` recolours a text or a shape's fill). Tools returning images wrap their result in `mcpRichResult`; `handleToolsCall` emits the JSON text block followed by MCP `image` content blocks.
- **Duplicates and the queue** (`mcp_sources.go`): `find_existing` matches `sourceKey` (normalised URL: BGG games as `bgg:<id>`, otherwise no scheme/`www.`/fragment/tracking parameters/trailing slash) on posts and news drafts, the raw URL in older documents, and optional text words. `get_draft_queue` counts open drafts with an `origin`. Posts carry `sourceUrl`/`sourceKey`/`origin`, news drafts `sourceKey` (from `articleUrl`)/`origin`, episode drafts `origin`; every MCP-created post or draft gets `origin` (`mcpOrigin`: the `origin` argument if it is a short slug, else `mcp`). Creating a draft over MCP fails once the team's `growth.maxAgentDrafts` (0 = no limit, Growth settings "Content agents") open origin drafts exist (`checkDraftCap`).
- **Speech** (`mcp_transcribe.go`): `transcribe` (a video or sound by `url` or `mediaId`, loaded like `get_image`'s files, sent through `transcribe.go`'s `transcribe` with the admin's OpenRouter key; returns `text`, `language`, `phrases` cut at pauses and sentence ends by `transcriptPhrases`, and `words` on request; 25 MB max). It does not render captions into a video: that stays in the browser editor.
- **Text**: `rewrite_instagram` (runs `RewriteInstagram`), `check_instagram_caption` (`caption_check.go`, the Go twin of `checkCaption` in `services/instagramGrowth.ts`: keep the two in step).

The wiki page `docs/wiki/Content-Agent.md` documents the setup and a sample agent run.

#### Built-in agents (`handlers/agents.go`, `agent_runner.go`, `agent_schedule.go`)
The Agents page (`/agents`, under Post Tools) runs agents inside SocialPod: a prompt on a schedule, executed by a model the user pays for. Settings live on the user (`User.Agent`, `models.AgentSettings`): the OpenRouter key (write-only, never serialised; `GET /api/agents/settings` reports `hasKey`/`keyHint`), the default model (Profile page, `AgentSettingsSection`) and the global prompt every agent gets on top of its own (Agents page). Agents (`agents` collection, `models.Agent`) belong to a user, not a team; a team token cannot manage them. REST: `GET/POST /api/agents`, `PUT/DELETE /api/agents/:id`, `POST /api/agents/:id/run` (409 while running), `POST /api/agents/:id/stop`, `GET /api/agents/:id/runs` (no steps), `GET /api/agents/:id/runs/:runId`, `GET/PUT /api/agents/settings`, `GET /api/agents/models` (OpenRouter's tool-calling models, cached an hour).

- **Schedule** (`agent_schedule.go`, unit-tested): `manual`, `interval` (≥ 15 min, from the last run), `hourly` (at `minute`), `daily` (`times` HH:MM, `weekdays` 0 = Monday, empty = every day), read in `timezone` (default Europe/Berlin). `AgentHandler.StartScheduler` checks every 30 s; claiming a due agent sets `running` and moves `nextRunAt` in one `FindOneAndUpdate`, so a slot never runs twice. On startup, runs left `running` are closed as interrupted.
- **Run** (`agent_runner.go`): the system prompt (`agentSystemPrompt`: how it runs, the current time in its zone, its origin, then the global prompt) and the agent prompt go through `chatMessages`; then `agentConversation.run` loops chat completions with tools until the model answers without a tool call (its summary), the step limit, the 30-minute timeout or a stop. Tools are `MCPHandler.toolDefinitions()` in OpenAI function format plus `web_search` (OpenRouter web plugin, same key and model) and `fetch_url` (`safeURLClient`). MCP tools run in-process through `MCPHandler.callTool` with a Gin context carrying the keys `MCPAuthRequired` would set (admin flags cleared), so agents have exactly the MCP feature set; never give them an admin path. Creating tools (`agentCreatingTools`) get `origin: agent-<slug of name>` unless the model passes one. Tool images go to the model as a user turn; a model that refuses images gets the run retried without them. Every step, tokens and cost are logged on the run (`agent_runs`, TTL 30 days) as it happens.
- The multi-turn loop builds its list with `messages: chatMessages(...)`/`messages := chatMessages(...)` and appends to it; `TestEveryAIRequestUsesChatMessages` accepts that form too.

**Single-use upload URLs** (`handlers/uploads_once.go`, `upload_tokens`, `models.UploadToken`): the MCP tool `create_upload_url {filename, expiresInMinutes?}` (default 60 min, max a day) answers with an `uploadUrl` (`APP_URL` + `/api/upload/once/<token>`) and the `url` the file will have. The client sends the file there itself, `PUT` with the file as the body or a multipart `POST` with a `file` field, without an Authorization header (the token is the authentication; only its SHA-256 is stored, a TTL index drops it a day after expiry). An upload claims the token atomically; a successful one spends it, a failed one (too large, empty, no bucket for a video) gives it back. The file name and type are fixed when the URL is made (the media library's types plus the editor's clips and sounds; images 30 MB, videos 200 MB, sounds 50 MB, fonts 10 MB) and stored as a temporary upload of the token's owner, so one nothing references is freed by the hourly cleanup a day later. The built-in agents do not get the tool (`agentHiddenTools`): they cannot send a file.

MCP image uploads: the `upload_image` tool accepts base64-encoded image data and a filename, stores the file (disk + MongoDB), and returns its URL. All create/update tools (`create_post`, `update_post`, `create_news_draft`, `update_news_draft`, `create_episode_draft`, `update_episode_draft`) also accept an `images` parameter — an array of `{data, filename}` objects with base64-encoded data — for inline image upload in a single tool call. Uploaded image URLs are merged with any `imageUrls` passed in the same call. Supported types: jpg, jpeg, png, gif, webp, mp4, mov.

### Frontend (`frontend/`)
React 19 + TypeScript + Vite. No state management library — auth state lives in `AuthContext`, everything else is local component state fetched via the `ApiClient`.

- `src/services/api.ts` — single `ApiClient` class that wraps all `fetch` calls; token stored in `localStorage`; redirects to `/login` on 401
- `src/contexts/AuthContext.tsx` — global auth state (`user`, `loading`, `login`, `logout`, `refreshUser`)

Dirtiness comes from native input/change events inside the panel, which fire only for real typing and picking — React's own state updates never trip it, so a dialog whose fields are filled in asynchronously does not look edited. ### Draft system
Three draft types exist across the application:

- **Post/Story/Reel drafts** — regular `Post` documents with `status: "draft"`. Created through the PostEditor (Calendar page). The Calendar page has a "Drafts" tab that lists all draft posts across types, with edit/schedule/delete actions. MCP: use `create_post` with `status: "draft"`.
- **News drafts** — stored in the `news_drafts` collection (`models/news_draft.go`). Managed through the News page's Create/Drafts tabs. REST: `GET/POST /api/news/drafts`, `GET/PUT/DELETE /api/news/drafts/:id`, `POST /api/news/drafts/:id/post`, `DELETE /api/news/drafts?posted=true` (bulk). MCP: `create_news_draft`, `list_news_drafts`, `get_news_draft`, `update_news_draft`, `delete_news_draft`, `post_news_draft`.
- **Episode drafts** — stored in the `episode_drafts` collection (`models/episode_draft.go`). Managed through the Episodes page's Create/Drafts tabs. REST: `GET/POST /api/episode/drafts`, `GET/PUT/DELETE /api/episode/drafts/:id`, `POST /api/episode/drafts/:id/post`, `DELETE /api/episode/drafts?posted=true` (bulk). MCP: `create_episode_draft`, `list_episode_drafts`, `get_episode_draft`, `update_episode_draft`, `delete_episode_draft`, `post_episode_draft`.

News and episode drafts follow the same lifecycle: create → list/browse → edit → publish (sends to webhook + optionally creates a social post + marks the draft `posted`). Drafts are submitted as `multipart/form-data` with `data` (JSON) and optional `images` fields.

Publishing never deletes a draft. It sets `posted: true` and `postedAt`, which moves the entry from the News/Episodes page's Drafts tab to its Posted tab; `GET /api/news/drafts?posted=true` (same for `/episode/`) and the MCP `list_*_drafts` tools with `posted: true` return that list, and every list defaults to open drafts only. Drafts saved before this existed have no `posted` field and count as open. The News and Episodes pages' Posted tabs each have a "Remove All" button that clears that list in one call (`DELETE /api/news/drafts?posted=true`, same for `/episode/`); the same endpoint without `posted=true` clears the open drafts instead. Submitting from the form (`POST /api/news/submit`, `POST /api/episode/submit`) may carry a `draftId`: the submitted content is then written back onto that draft before it is marked posted, so the Posted entry records what actually went out rather than the last saved state. A submit without `draftId` — one that was never a draft — creates no entry.

The News and Episode forms hold a single image, and the backend keeps the `imageUrls` it is given alongside any uploaded file. A local image — a fresh pick, or a crop of the draft's own stored image, which has no local file behind it — is therefore sent with an empty `imageUrls` so it replaces what was stored rather than being appended to it. After a draft save the form adopts the URLs the server returns, so the next save neither re-uploads the same crop nor works from an image cleanup has already freed.

### Post create/update API contract
Posts are submitted as `multipart/form-data` with two fields: `data` (JSON string of the post object) and `images` (zero or more binary files). Uploaded files go after the `imageUrls` unless `imageUrls` places them: an entry `upload:<n>` stands for the n-th file (`placeUploadedImages` in `posts.go`), which is how the PostEditor keeps a carousel's order when kept and new images are mixed. Its image grid (`SortableTiles`, `Common/SortableTiles.tsx`: mouse after 4 px, touch after a 250 ms hold, keyboard) drags a post's images into order, with Photo and Create tiles after them; stories and reels hold one and are not sortable. This applies to both the REST API and the frontend `ApiClient.createPost`/`updatePost` methods. Given an `onProgress`, those two send through `uploadWithProgress` (XHR) instead of `fetch`; the PostEditor passes one through `onSave`'s `SaveOptions` whenever a save carries files and shows an upload bar above its footer (a reel's MP4 is uploaded only at save time, then stored in the bucket before the answer, the bar's "Storing…" phase).

The PostEditor takes images three ways — the file picker, a drop on the image area, and a clipboard paste — all funnelled through `addFiles`, which drops whatever the post type can't use (a post takes images, a story either, a reel video). Like the News form, the empty image area is itself the drop target and says so. A pasted or dropped image opens the cropper right away; a picked one only when it isn't square already. The cropper carries the same Overlay picker as the Episode form — the team's watermarks plus None — but unlike News and Episode, which preselect the team's configured creator watermark, it opens on None every time, so an overlay on a post image is always a deliberate pick. Picking one draws it over the crop area and bakes it into the output; picking None takes it off again.

The PostEditor's BoardGameGeek import has an "Image only" checkbox (hidden for reels): checked, it calls `GET /api/bgg/fetch?…&imageOnly=true`, which skips the AI text, hashtags and handle lookup and returns just the processed cover, and the cover replaces the post's first image (or is added when there is none); text, collaborators and every other field stay untouched.

### Watermarks (`handlers/media_watermarks.go`)
Watermarks are not a collection of their own: they are media library images flagged `watermark: true` (`MediaItem.Watermark`; only an image can be one, `updateMediaItem` refuses others). Everything that takes a watermark (the team's overlay roles `bggWatermarkId`/`newsCreatorWatermarkId`/`episodeOverlay*Id`, a convention queue's `watermarkId`, `compose_image`'s `watermarkId`) holds a media ID and loads it with `findMediaItem`. `MigrateWatermarksToMedia` moves the documents of the former `watermarks` collection into `media` under their old IDs, so those references keep resolving, and drops the collection; it runs on startup and after a restore (an old backup brings the collection back), and is idempotent. `GET/POST /api/watermarks`, `PUT/DELETE /api/watermarks/:id` remain for API clients (the n8n node) as the library narrowed to watermarks; the frontend's overlay pickers use `GET /api/watermarks`, and `GET /api/media?kind=watermark` lists the same entries. Deleting a watermark deletes the library entry; unmarking keeps the image.

### Image editor (`components/Common/ImageEditor/`)
The pencil on an image (PostEditor, convention queue items) opens `ImageEditor`, our own full-screen editor on Konva (`react-konva`). Above 768px the tool tabs are a vertical rail and the current tool's controls a fixed-width, scrolling column (`.ie-panel`), both left of the picture, so the picture never resizes as the controls change. At 768px and below (`PHONE_QUERY`, `phone` state) neither is rendered: the editor has a phone layout instead (`PhoneParts.tsx`, still and video alike), modelled on Canva's and Adobe Express's mobile editors. A bottom bar (`PhoneBar`, `phoneBarItems`) holds the add tools with nothing selected (Crop/Filters or Canvas, Templates, Media, Text, Shapes, Brush, Video) and the selected object's tools once one is tapped (text: Edit, Font, Size, Colour, Align, Style; image: Replace, Clip, Opacity, Corners, Border, Fit; shape: Shape, Fill, Border, Corners, Opacity; all: Animate in a video, Centre), with Done to deselect. A tool opens one control at a time in a tray laid over the bottom of the picture (`PhoneTray`, `phoneTray`; chips pick among a tool's few controls, e.g. Animate's Timing/Comes in/While shown/Goes out, `animateControls(l, part)`), so the picture never resizes; `phoneToolIds` lists the tools valid for a selection and an effect closes a tool that no longer is. Crop and Brush set `tab` while their tool is open and the stage otherwise rests on `restTab`. Templates, Media, the Objects list and a video's length and music open as bottom sheets (`BottomSheet`, half height, dragged up to nearly full); the media sheet closes once something is added. A small toolbar under the selected object (`MiniToolbar`, placed in a layout effect, hidden while it moves or a tool is open) duplicates it (not a clip), moves it up or down the stack, opens the Objects sheet and deletes it. Two fingers pinch, turn and move the selected object (`onStageTouchStart`/`pinchedLayer`; secondary pointers never pick a layer). A cancelled touch (`touchcancel`/`pointercancel`, an edge swipe or long press) ends a resize, turn or pinch in progress: Konva's Transformer listens for touchend only and would otherwise go on transforming with stale hit areas; on touch the turn handle's hit area is widened (`anchorStyleFunc`), and on a touch screen a second, unhurried tap on the same spot selects the next object down (`onStagePointerUp`, `layersUnderPoint`). The desktop panel and the phone share their pieces (`cropControls`, `formatChips`, `templateList`, `mediaLibrary`, `videoSettings`, `alignButtons`, `borderStyleChips`, …). Templates and the media library are grids of small previews (two columns in the desktop column), the library loading all its images at once (the search only narrows them). Tools: crop with aspect presets, filter presets plus brightness/contrast/saturation, media library images (one Media tab: tap to add, or upload a file into the library and add it; its Watermarks filter narrows it to the library's watermarks, which are badged in the full list, go into the bottom-right corner unless shaped like the crop, and are marked as such when uploaded in that view) as movable/scalable/rotatable layers with opacity, shapes (`ShapeLayer`: box, circle/ellipse, triangle, equalizer; fill colour or none, border width and colour on the outline with round joins, box corners, opacity; stretched freely, Shift keeps proportions), brush paint (`PaintLayer`: strokes with size, feather, colour and opacity, painted on the Brush tab, whose Move mode picks and drags layers instead; new strokes go into the selected paint layer wherever it is in the stack, otherwise a new one on top, and the stroke being painted is drawn at that place in the stack, so it shows as it will end up; picking a paint layer in the Objects list while on the Brush tab keeps the Paint/Move mode; the feather is the stroke's canvas shadow with the stroke itself drawn off the canvas (`paintStrokeAttrs`), so any blur is cheap — for soft darkening behind text), and text layers (typed on the picture itself: `InlineTextEditor`, a textarea laid over the hidden Konva text in its font, size, colour, outline, shadow and angle, opened by double-click/double-tap, Enter on a selected text, the Text panel's "Edit text" or adding a text (not on touch); typing keeps the alignment point (`retypeText`), one edit is one undo step, Esc or a click outside finishes and a text left empty is removed; font, a font size field in source pixels that resizes about the text's centre (`resizeText`), left/centre/right alignment of the lines, colour, bold, outline, shadow). The arrow keys move the selected layer one screen pixel (ten with Shift), a run of presses one undo step. Image layers are Konva groups built by `imageLayerParts` (stage and `renderEdit` alike): optional rounded corners (`cornerRadius`, percent of the shorter side), a border outside the image (`border`: style solid/dashed/dotted/double/glow/offset, width in source pixels, colour) and `srcCrop`, the part of the image shown. Every layer (image or clip, text, shape, paint) takes a blend mode (`blend`, `BLEND_MODES`: multiply, screen, overlay, … luminosity; normal when absent), the canvas's composite operation set on the layer's own node by `blendAttrs` (image/shape group, paint group, `textLayerAttrs`), so the stage, `renderEdit` and the video export blend alike; the desktop panels show it as a Blend list, the phone bar as a Blend tool with chips, and `toTemplate` keeps it. Pasting an image (Ctrl/Cmd+V, caught in the capture phase before the page below sees it) or the image controls' Replace button uploads it (`POST /api/upload`, so a template refers to it by URL). Replace always takes the selected image layer's place, cropped to fill its frame (`srcCrop`) and keeping corners and border; a paste does so only for a template's placeholder (`placeholder`, set on image layers a template brings, not stored), otherwise the pasted image is added whole in the middle, so pasting never swaps out an image the user just added (it is still selected) or clips a pasted image to that layer's frame. Fonts are the media library's fonts (`GET /api/media?kind=font`) followed by a built-in list of system fonts; the editor takes no font files of its own. A library font is registered as `SocialPod Media <id>`, so wherever a family goes into CSS (the in-place text field, the font chips and list, the Objects list) it goes through `cssFontFamily`, which quotes every name with a space as Konva does for the canvas: unquoted, an id starting with a digit is invalid CSS and the browser falls back to its default font. Colour swatches start with the media library's colours (`kind=color`, the entry's name shown on hover), then the built-in swatches and a custom picker. Everything is held in source-image pixels (`editorModel.ts`): the crop is a window onto the original and layers sit on the original, so re-cropping never shifts them. Undo/redo (header buttons, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y outside text fields) snapshots that edit state — crop, aspect, adjustments, layers — before each change; every change goes through `checkpoint`, a keyed change (slider, typing, colour picker) joins the previous step while it keeps coming within a second, and a drag or resize is one step however long it lasts. Moving a layer snaps it with smart guides (`snapping.ts`, pure): to the edges and centres of the page (the crop) and of the other layers, and to equal spacing (halfway between its neighbours, or the gap of a neighbouring pair in the same row, page margins included), drawing the guide lines and the matched gaps with their size in source pixels; the magnet in the header turns it off (remembered in `localStorage`), Alt skips it for one drag. Resizing and rotating do not snap. Layers are stacked in the order of the `layers` array (later on top), which the Konva stage and `renderEdit` both follow. The Objects list on the right edge (`LayerList.tsx`, `@dnd-kit/sortable`; the header's layers button shows and hides it, open by default; on a phone it opens as a sheet) lists them top first above a fixed Background row; tapping a row selects that layer, dragging restacks (one undo step). A press inside the selected layer's box keeps it selected and drags it even where another layer lies on top (`onLayerPointerDown`/`holdSelected`: the covering node stops being draggable until the pointer is let go, the drag starts once the pointer moves), so a layer under a full-frame image can be picked in the list and moved on the picture; a tap or click that does not move still selects the layer on top. On a touch screen only a layer picked in the Objects list is held that way (`pickedInList`): one selected on the picture or just added (a full-frame clip, say) would otherwise take every drag meant for the objects on top, so there a press on another object selects and drags that one. The stage's layer finds what is under the pointer by geometry (`hitTest.ts`, `geometricHitTest`: each shape's own box, turned and scaled with it, widened by its hit stroke, inside its groups' clips), not Konva's colour-keyed hit canvas: Safari 26's fingerprinting protection adds noise to canvas readback, so on an iPhone Konva's hit test found nothing or a random handle and objects could not be dragged or resized. On a touch screen a tap that hits no layer takes the topmost one within `TOUCH_SLOP` (16 screen pixels) of its box, for thin texts, outlines and strokes. On a phone the timeline's layer bars show only while the Animate tool is open. The screen shows filters on a reduced copy; `renderEdit` builds the output separately at full resolution (longest side capped at 4096 px) and returns a JPEG. `guideOverlay` draws an overlay over the crop for reference without exporting it — the convention queue passes its queue watermark, which the backend stamps at post time. **Image drafts** (`handlers/image_drafts.go`, `models/image_draft.go`, collection `image_drafts`) keep unfinished editor work to come back to. The header's "Save draft" (or Ctrl/Cmd+S) stores the whole edit as an `EditorDraft` (`editorModel.ts`): the design via `toTemplate` over the picture's full size, so layers stay in its own pixels, and for a photo `photo: {src, crop, aspectId, adjustments}`; a local photo (blob URL) is uploaded first. The first save asks for a name, later ones update the same draft. The Templates tab lists the drafts ("Your drafts", above the templates; delete on each tile), and picking one restores it exactly (`restoreDraft`, `instantiateTemplate` with `placeholders: false`), photo or blank canvas whatever the editor was opened on, and clears undo; the editor's photo is therefore state (`photoUrl`), not the prop. Whatever opened the editor still gets the final render. Drafts are the saving user's own (filtered by `userId`, max 200): `GET/POST /api/image-drafts` (the list leaves out `design`), `GET/PUT/DELETE /api/image-drafts/:id`, multipart `preview` + `design` (`checkImageDraft`: the template outline via `checkDesign`, up to 20000 px a side and 2 MB) + `name`; `url` (the preview) and `designUrls` (photo and image layers) are in `uploadReferences`. **Post designs** (`handlers/post_designs.go`, `Post.Designs`/`DesignURLs`, `models.PostDesign`) keep what was made in the image editor editable in the post itself. The PostEditor opens all three editors (edit image, Create Image, Create Video) with `keepEdit`, so `onSave` also gets the whole edit (`currentEdit`, an `EditorDraft` as for an image draft, a local photo uploaded first), and the item keeps it (`ImageItem.design`); the post sends them as `designs` (`{imageUrl, design}` for a stored image, `{file: n}` for the n-th file of the request, whose URL the backend fills in). The pencil on such an item, a video included, opens the editor on the edit (`draft` prop → `applyDraft`, the core of `restoreDraft`) instead of on the exported file; it is badged "Editable". The editor's "Keep unexported" (`onKeep`) hands over the edit and a still without exporting: the item becomes a design-only one (`kind: 'design'`, the still uploaded as its `previewUrl`, badged "Not exported", in the Calendar's Drafts tab too). A post holding a design with no `imageUrl` can only be a draft: the PostEditor and the backend (`errUnexportedDesign`, on create, update and MCP) refuse to schedule it until it is exported. A handed-over edit's clips and sounds are taken off the editor's release list (`handOver`, `editUploadUrls`), so closing the editor does not free them before the post is saved; `designUrls` (the photos, layers, clips, music and stills the designs use) is in `uploadReferences`. On an update `designs` replaces the stored ones; absent, the stored ones stay, less those of images the update drops (`updatePostDesigns`). MCP's `create_post`/`update_post` take the same `designs` (a template or an editor draft, as an object or JSON string; `file` indexes the call's inline `images`), which is how an agent leaves an editable draft or a video it cannot render; `list_posts` leaves the designs' JSON out, `get_post` has it, and `list_media` with `design: true` returns templates' JSON to start from.

**Clipart** (`handlers/clipart.go`, `ImageEditor/clipart.ts`): the Media tab's Clipart filter searches Iconify (`GET /api/clipart/search?q=`; `ICONIFY_API_URL` for a self-hosted copy of its API, default the public one) across a fixed list of icon sets whose licence needs no credit (`clipartSets`, and the set's reported licence must still be in `clipartLicenses`: MIT, ISC, Apache-2.0, CC0), cached an hour. The backend resolves aliases and their flips and turns like `@iconify/utils` (`iconifyJSON.resolve`, unit-tested against its output) and answers each icon as an SVG body with its view box, so the browser never calls Iconify. The editor recolours `currentColor` icons in the picked colour (emoji keep theirs), renders a 1024 px PNG, uploads it (`POST /api/upload`) and adds an ordinary image layer, so templates, drafts, video export and `compose_image` need nothing of their own. **OpenClipart** (`handlers/clipart_openclipart.go`) is searched as well once an admin stores its credentials on the Settings page (`AppSettings.OpenClipartAPIKey`/`OpenClipartAppID`/`OpenClipartAppSecret`, secrets write-only): `GET /api/v2@beta/search?q=` with the `x-openclipart-apikey` header. Its app tokens are JWTs that last a day, so with the app ID and secret stored an expired token is replaced from `apps/getToken` and the new one saved (`openClipartToken`); without them an expired token only puts an error in the search answer's `errors`, and Iconify still answers. The search answer's file entries are undocumented beyond `data.files`, so `parseOpenClipartSearch` reads them loosely (id, title, URLs on openclipart.org sorted into thumbnail, PNG and SVG by key and extension). Results carry `source: "openclipart"`, `previewUrl` and `fileUrl`; the editor lists them in their own section, in their own colours, and adds one through `POST /api/clipart/openclipart/import {url}` (openclipart.org URLs only, redirects included): a PNG or JPEG is stored as an upload, an SVG comes back as markup that `svgDocumentPng` renders and uploads.

The square-only `ImageCropper` is still separate and still used on add/paste/drop and by the crop buttons.

Without an `imageUrl` the editor draws on a blank canvas (`canvas`: size and background colour, part of the undo snapshot): a Canvas tab (formats `CANVAS_FORMATS`, 1:1/4:5/9:16/16:9 at 1080 px, which refit the layers with `fitLayers`, and the background colour) replaces Crop and Filters, and the Background row of the Objects list shows the colour. `onSave` gets the rendered JPEG and the design as an `EditorTemplate` (`toTemplate`: canvas size, background, layers with image layers by `src` URL). **Templates** are such designs kept in the media library. The Media Library's "New Template" (`TemplateFormModal`: name, format, description, tags) opens the editor on a blank canvas, and its save stores the template (`POST /api/media/templates`, multipart `preview` = the render, `template` = the JSON, name/description/tags); the brush on a template card ("Edit design") reopens it and `PUT /api/media/templates/:id` replaces design and preview. A template entry has content type `template/socialpod` (`kind=template`), `url` = its preview, `template` = the JSON, and `templateUrls` (server-side, from the image layers' `src`; `checkTemplate` validates the outline) in `uploadReferences`, so the images a template uses stay while it does. `TemplateFormModal` also picks the type: a **video template** opens the editor in video mode (`video` + `designOnly`), where Save hands over the frame at the playhead as the preview and the design with `duration`, `audio`, the layers' `anim` and clips, instead of exporting the MP4; the editor reopens it in video mode when the stored design has a `duration` (`isVideoTemplate`). The card and the editor's tile mark it with a film badge. The editor's Templates tab lists them: on a blank canvas a template replaces the design (canvas included, and a video template's length and music in video mode), on a photo its layers are laid over the crop, scaled to it. A still editor leaves video templates out of the list. **Built-in templates** (`systemTemplates.ts`, `SystemTemplateTile.tsx`) are SocialPod's own, beside the team's: the Templates tab has two tabs, "SocialPod" and "Yours" (drafts and the library's templates; shown first when there are any). Each design (headline, breaking news, spotlight, review score, new episode, top 5, list item, quote, this or that, giveaway, coming soon, live from, crowdfunding, snapshot, game night, did you know) is a function of a `Frame` and comes in 1:1, 4:5 and 9:16; on 9:16 its content keeps out of the reel's header, icon column and caption area. They use plain colours and the built-in fonts (`BUILTIN_FONTS`, now in `editorModel.ts`) on purpose, for the user to restyle. Texts are placed by measuring them (`text()`: anchor point, shrunk to `maxWidth`), so they stay put whatever font a device falls back to. Pictures are placeholder images in `frontend/public/template-assets/` (served by the frontend; `resolveUrl` does not prefix them with the API base), filled with `srcCrop`, so Replace or a paste swaps one out like any template placeholder. In a video every non-backdrop layer gets an enter effect from the start, each a little longer than the one before (`videoAnim`), over 8 s, so the design is whole where the editor opens it. **Reel templates** (`REELS`, `Design.reel`: length, poster time, 9:16 only) are videos only and listed first, with a film badge, in a video editor (a still editor leaves them out): kinetic intro, countdown reveal, top 3 countdown, review verdict, podcast clip (the cover spins as a record over a rippling row of dots), breaking live, versus, save the date, quote typewriter, giveaway hype, photo recap and Tabulaludo review (the weekly review podcast's intro: the game's cover over an equalizer in the podcast's colours, laid out clear of the auto-captions). Their layers carry their own timing, scene after scene (`at(start, end, enter, exit, {in, out, loop})`, `timed` for a group), not the cascade; photos push in with the `slow-zoom` loop effect (also offered in the Animate tab). On a photo only the designs with a full-frame backdrop picture (`overPhoto`) are listed, and the photo takes that picture's place. Previews are rendered in the browser on first show and cached for the session (a reel's at its `poster` time); in a video editor a tile plays its template while the pointer is over it or it has focus (`SystemTemplateTile`: a small Konva stage drawn every animation frame by `drawSystemFrame`, the same `animStateAt`/`buildAnimatedLayerNode` the export uses), not on touch, where a tap picks it. The format filter defaults to the one closest to the canvas or crop. A team template saved from a built-in one can still hold placeholder pictures: the backend reads `/template-assets/` from the embedded frontend (`handlers.FrontendFiles`, set in `frontend.go`) so `compose_image` can draw them. `list_media` reports a video template's `templateDuration`; `compose_image` draws it as a still. A blank canvas opens on the Templates tab, or on Canvas when the library has none. The PostEditor's "Create Image" (footer, and the empty image area; not for reels) opens the editor on a blank 4:5 canvas, 9:16 for a story, and adds the result to the post (a story's replaces its image) without going through the cropper. The News and Episode forms have a "Create Image" button too (empty image area and beside Crop/Replace): it opens the editor on a blank 1080×1080 canvas, and the result goes through the form's cropper like any picked image, which adds the overlay and keeps it under the 1 MB limit.

**Videos** (`video` prop; `animation.ts`, `Timeline.tsx`, `videoExport.ts`, `mediaSync.ts`). The PostEditor's "Create Video" (reels and stories: footer and the empty image area) opens the editor in video mode on a blank 9:16 canvas: the design gets a length (`duration`, 3–180 s) and music (`audio`, an `AudioTrack`: a sound file's `src`, `start` in the video, `trimStart` into the file, `volume`, `fadeIn`/`fadeOut`, the file's `duration`), both part of the undo snapshot, and every layer an optional `anim` (`LayerAnim`: `start`/`end` in seconds, `end` absent = to the end of the video; an enter effect fade/slides/zoom/pop/wipes/flicker/tumble/spin/bungee/shrink/typewriter (texts only), a loop effect pulse/float/wiggle/spin/breathe/bob/yoyo/jitter/blink/flicker, an exit effect fade/slides/zoom/wipes/flicker/tumble/spin/pop/grow, each with its duration; several modeled on Adobe Express's presets, random-looking ones (flicker, jitter) from a fixed `noise` seeded per layer so preview and export match). A layer's `anim` can also carry **keyframes** (`keys`, `Keyframe`: `t` in seconds after the layer's start, so keys move with its bar; a shift `x`/`y` in picture pixels, `scale` and `rotation` about the layer's centre, an `opacity` factor, and an `ease` to the next key: smooth/linear/ease-in/ease-out/hold). `keyValuesAt` interpolates them and `animStateAt` starts from that before the effects, so they combine with enter, loop and exit effects and export the same. They sit on top of the layer's own attributes, which stay put: once a layer has a key, dragging, resizing (evenly, about its centre), turning, pinching, nudging or centring it on the picture sets the key at the playhead instead (`keyGesture`, `setKeyAt`, which adds one there from the interpolated values when there is none). The Animate tab's Keyframes section (a tray part on a phone) adds and removes the key at the playhead, steps between keys and sets Move X/Y, Size, Turn and Opacity and the ease; the timeline shows the keys as diamonds on the layer's bar, clicked to go to one and dragged to retime it, and trimming a bar's start keeps them where they are in the video. A layer without `anim` shows the whole time and does not move. **Clips** are image layers with a `clip` (`ClipInfo`: `trimStart` into the video, `volume`, the video's `duration`) whose `img` is an `HTMLVideoElement` (`loadVideo`) and `src` the video, so they move, resize, turn, stack and take corners, borders and opacity like any image; Replace turns one back into a picture. The Media tab's Clips filter (video mode only) lists the library's videos and uploads a clip, which goes up as a temporary upload (`POST /api/upload/temp`, see Upload lifecycle) unless "Keep uploads in the media library" is ticked; the music comes from the library's sounds (`kind=audio`) or an upload the same way, on the Animate tab with nothing selected, which also has an "Upload a clip" button (the same upload, without going through the Media tab; on a phone the Video sheet closes once the clip is on the picture). **The clip sequence** (`sequence.ts`): a clip added in the editor (one or several files at once, or from the library) joins the sequence (`clip.seq`), the clips that play one after the other in the order they are stacked (later on top, as an incoming clip must be). Their spans are laid out, not chosen: `layoutSequence` runs on every change of the layers (the editor's `setLayers` wraps it), packing them from 0 with each clip's length (`anim.end - anim.start`) and overlapping two clips by the transition between them (`clip.transition`, the one into a clip: cut, crossfade, dip, pushes, wipes, zoom, slide over; at most half of either clip), and writes the transitions actually played as `clip.into`/`clip.out`, which `animStateAt` (`applyTransitions`) and the sound's crossfade (`clipFadeIn`/`clipFadeOut`) read. The timeline shows the sequence as one Clips track instead of a bar per clip: a clip dragged takes the nearest place (`moveInSequence`), its ends trim it (`trimClip`: the start moves `trimStart`, the end the length, within the video), and the mark between two clips opens the transition controls. Adding or trimming clips lengthens the video to hold them, and shortens it with them when it was as long as they were (`fitToSequence`). "Play in the clip sequence" takes a clip out (an overlay keeping its span) or puts it back at the end; clips from templates and older designs are not in it. A clip shows its frame at `clipTimeAt` (holding the last one once it has run out) and plays its sound at `clipGainAt` (its volume, faded with the layer's in/out effects, so a crossfade crosses the sound too), the music at `musicGainAt`. `animStateAt` is a pure function of the time, and the stage and the export both draw a layer inside a group built by `animGroupAttrs` (shift, scale and turn about the layer's centre, opacity, visibility, a wipe's clip; a typing text by `animatedTextAttrs`), so preview, scrub and export show the same frame. A video design opened or restored (template or draft) starts at `openingTime`, once the layers that come in at 0 have settled, not at 0, where they are still faded out and shifted off their place; picking a layer that is hidden or still coming in moves the playhead to `settledAt` (`seekInto`). The preview plays the clip videos and an `Audio` element for the music along with the playhead (`syncMedia`, re-seeking when they drift), and stops them when the editor closes. The Animate tab sets the length and music (nothing selected) or the selected layer's timing and effects; the timeline under the picture plays (Space), scrubs, and has a bar per layer (clips in blue) and one for the music, dragged to move them or by a layer's ends to change it (one undo step a drag). "Export video" renders 30 fps frames offline and encodes them with WebCodecs (H.264) into an MP4 with its index up front (`mediabunny`, `fastStart: 'in-memory'`): clip frames are decoded from the files themselves (`CanvasSink`), and the clips' sound and the music are mixed in an `OfflineAudioContext` and encoded as AAC; `onSave` gets it as `video/mp4`. A browser without an AAC encoder of its own (Chromium on Linux, Brave, Firefox) gets FFmpeg's as WASM (`@mediabunny/aac-encoder`, loaded only then, `canEncodeAac`); one without H.264 is told so. `toTemplate` keeps `duration`, `audio` and the layers' `anim` only when given a duration, so a still design never carries them; `clip` stays with its layer. The backend's `checkDesign` lists clip and music files among the design's upload URLs (so drafts and templates keep them) and ignores the rest; `compose_image` leaves a template's clips out of a still unless an image is swapped in (`list_media` marks them `clip`). Drafts saved from a video keep it all and restore it; their preview is the frame at the playhead. The PostEditor passes `safeZone` (`reel` for a reel, `story` for a story's video, created image or edited image), as does the Media Library's template editor (`reel` for a video template, `story` for a still); the editor shows it only while the crop or canvas is 9:16 (`zone`): a header button (phone icon, remembered in `localStorage`, on by default; not on a phone, where the zone always shows and the header also leaves out redo and says "Export" for "Export video", with the draft and template buttons as plain icon buttons, so it fits a 360px screen) shades where Instagram's own interface covers the frame (`safeZones.ts`, fractions of 1080×1920: a reel's header, icon column and caption/handle/audio area; a story's progress bar and reply field), drawn over the stage only and never exported. **Equalizer** (`equalizer.ts`): a shape kind (`shape: 'equalizer'`, `bars` 4–64, `mirror` to grow from the middle, `cornerRadius` per bar) drawn by `shapeLayerParts(l, levels)` as bars over an empty box (which picks and frames the layer). For a reel that has only sound: picking music for a video with no clip adds one in the same undo step (`pickSound`), and the music controls offer "Add equalizer" and "Video as long as the sound". `audioLevels` decodes the music once per session (22.05 kHz mono, at most 10 minutes) into 32 log-spaced bands per video frame (`spectrumLevels`: FFT, each band scaled between its own quiet and loud ends, falling back slower than it rises); `equalizerLevels` (`animation.ts`) samples them at the music's time and fades them with it, so the stage and `renderVideo` draw the same bars. Without analysed music the bars dance on a made-up pattern (`idleLevels`, also the built-in templates' previews), and a still shows them at rest (`restLevels`), which `compose_paint.go` (`equalizerRest`, `equalizerBars`) draws the same: keep the two in step. **Auto-captions** (`captions.ts`, the Captions section of the video settings, i.e. the Animate tab with nothing selected and the phone's Video sheet): `speechAudio` (`videoExport.ts`) mixes the clips' sound alone, without the music (usually a song), as 16 kHz mono WAV, or the music alone when no clip has any sound (a reel of only sound, such as a podcast snippet; "Make captions" is enabled with a clip or music), `POST /api/transcribe` (`handlers/transcribe.go`: OpenRouter's OpenAI-compatible `/audio/transcriptions`, Whisper with `verbose_json` and word timestamps, the next model in `transcribeModels` on a 4xx refusal; segment-only answers are spread over their words) returns the words in video time, `captionCues` cuts them into captions (one word, a few, or phrases; also at a pause or a sentence end) and `captionLayer` lays each as a text layer marked `caption`, timed by its `anim` with the style's enter effect, centred at Top/Middle/Bottom (Bottom above a reel's caption area, at most 74% of the width to stay clear of the icons), broken into two lines or shrunk to fit. They are ordinary texts (retype, move, restyle one by one); the section's style, font and place restyle all of them (`cueOf` keeps their words and times), "Redo captions" replaces them and "Remove captions" deletes them, each one undo step. The video editor's header also has "Save template" (`saveAsTemplate`): it asks for a name and stores the design, length, music and animations included, as a media library template (`POST /api/media/templates`, preview = the frame at the playhead), which then shows under Templates.

### Upload lifecycle
Every uploaded file goes through `internal/uploadstore` and is referenced by URL (`/api/uploads/<file>`) from whichever document owns it. Videos and sounds (`video/*`, `audio/*`) are only ever stored in the bucket: without one `Save` refuses them (`ErrNeedsBucket`) rather than put them in a database record, which covers a post's rendered reel as much as a library clip. With an S3 bucket configured (`AWS_S3_BUCKET_NAME` + credentials, the same bucket as the backups; `uploadstore.Configure` in `main.go`) its bytes are stored in the bucket under `uploads/<file>`, and the `uploads` collection keeps only a record (filename, content type, size, `storage: "s3"`). Without a bucket the record carries the bytes (`data`), as every record did before. `UPLOAD_DIR` is only a cache: `Save` writes it, `Read` serves from it and refills it from the bucket or the record. Never read or write `UPLOAD_DIR` or the `uploads` collection directly: store through `storeUploadBytes`/`uploadstore.Save`, read through `uploadstore.Read` (or `readImageBytes` for URLs), delete through `uploadstore.Delete`. On startup with a bucket, `uploadstore.MigrateToBucket` moves the bytes of records that still carry them into the bucket in the background (idempotent; a failure is retried next start and the record keeps serving meanwhile).

`handlers/uploads_cleanup.go` frees those files again. Deleting a post, a news or episode draft (single or bulk), a watermark, or a convention queue item or queue removes the images it held; updating one of those documents frees the images the update dropped, as does submitting a draft whose image changed. Nothing is deleted blindly: `cleanupUploads` first checks every collection/field that can hold an upload URL (`uploadReferences`) and keeps any file still pointed at, because the same URL is routinely shared — submitting a draft gives its image to the post it creates, and a consumed convention queue item hands its image to the post it spawns. Cleanup is best-effort and never fails the request it follows; a reference check that errors keeps the files.

**Temporary uploads** (`handlers/uploads_temp.go`) are the image editor's clips and sounds for a video (and the files sent to single-use upload URLs, see the MCP section): `POST /api/upload/temp` (multipart `file`: mp4/mov/webm up to 200 MB, mp3/m4a/aac/wav/ogg up to 50 MB) stores one with `temporary: true` and the uploader's `ownerId` on its record. Usually nothing ever owns them (the video is rendered into a post, which keeps only the rendered file), so the editor releases its own when it closes (`POST /api/upload/release {urls}`, sent with `keepalive`; only the caller's temporary uploads), and `StartTemporaryUploadCleanup` does the same hourly for those older than a day (a closed tab, a crash). Both go through `releaseTemporaryUploads`: a file something references (an image draft's or template's `designUrls`/`templateUrls`) loses its temporary mark and stays, the rest are deleted with `cleanupUploads`.

Automatic cleanup only covers uploads a document owned. Two kinds are left over: the backlog from before cleanup existed, and imports abandoned before anything referenced them (`POST /api/upload`, `/api/upload-from-url` and captures store a file immediately, minutes before the post or draft that will reference it exists). `handlers/uploads_sweep.go` clears both — an admin-only scan/sweep over the whole store, reachable from the Storage card on the admin Settings page:

- `GET /api/admin/uploads/orphans` — scan, delete nothing
- `POST /api/admin/uploads/sweep` — scan, delete nothing
- `POST /api/admin/uploads/sweep?delete=true` — delete what it finds

Both take `minAgeHours` (default 24), the age guard that spares uploads an open editor has stored but not yet referenced. The sweep reads every part of the store (the `uploads` collection, the bucket's `uploads/` and `UPLOAD_DIR`), so a record whose bytes are missing, or an object or file with no record, is found too, and reports totals, orphan counts and bytes, and a sample. A failed reference scan aborts it rather than treating everything as unreferenced.

The media library (`media` collection, `models/media.go`, `handlers/media.go`: `GET/POST /api/media` (`?kind=image|video|audio|font|color|template`), `POST /api/media/colors`, `POST /api/media/templates`, `PUT /api/media/templates/:id`, `PUT/DELETE /api/media/:id`) references uploads by `url`. A colour entry has no file: `url` is empty and `color` holds `#rrggbb`/`#rrggbbaa` (`normalizeColor`, content type `color/hex`), and its description says how to use it; `color` can be changed on colour entries only. Besides images and videos (clips for the image editor's videos) it takes sounds (mp3, m4a, aac, wav, ogg; `kind=audio`, the editor's music) and .ttf/.otf fonts, checked by `checkFontUpload` (parses, Latin glyphs incl. umlauts, no collections, max 10 MB, stored as the type its contents show), for agents to set `compose_image` text in; `media.url` is in `uploadReferences`, so a file stays while the library holds it, and deleting an entry frees it unless something else uses it. Images `compose_image` builds belong to nothing until a post references them (or `addToMedia` records them), so the sweep clears unused ones after its age guard.

**When a new model starts storing image URLs, add it to `uploadReferences`** — otherwise a delete elsewhere, or a sweep, will free files that model still needs.

### Full-system backups (`handlers/system_backup.go`, `internal/backup/`, `internal/objectstore/`)
Ported from PlotGod. An admin sets, on the Settings page's Backups card (`components/Admin/BackupsCard.tsx`), a schedule (`off`/`hourly`/`6h`/`12h`/`daily`/`weekly`), the number of backups to keep (1–365) and the encryption passphrase (min 12 characters, write-only), all in the `backup_config` singleton (`models.BackupConfig`). A backup dumps every collection as canonical Extended JSON (`db/<collection>/<n>.jsonl` + `manifest.json`), plus, with a bucket, every uploaded file whose record says it is there (`files/<name>`, listed in the manifest's `files`; `bucketFiles`), into a ZIP whose entries are WinZip AES-256 encrypted (`backup/aeszip.go`; opens in 7-Zip, WinZip, Keka). It is stored as `backups/socialpod-backup-<UTC time>-<kind>.zip` (kind `scheduled`, `manual`, `pre-restore`) in the S3-compatible bucket configured by `AWS_S3_BUCKET_NAME`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (+ optional `AWS_ENDPOINT_URL`, `AWS_DEFAULT_REGION`); `objectstore` speaks SigV4 with the standard library. Without a bucket, backups are off but restoring an uploaded file still works.

- REST (admin only): `GET/PUT /api/admin/backups/config`, `GET /api/admin/backups` (newest first), `POST /api/admin/backups` (starts one in the background, 202), `GET /api/admin/backups/:name/download`, `POST /api/admin/backups/:name/restore {passphrase?}`, `POST /api/admin/backups/restore-upload` (multipart `file`, `passphrase`), `DELETE /api/admin/backups/:name`. A wrong passphrase answers 422, not 401 (the frontend logs out on 401). One backup or restore runs at a time (409 otherwise).
- The scheduler (`StartScheduler`) checks every 5 minutes; after a failure it retries at most every 30 minutes. Scheduled and manual backups prune to the retention count afterwards, counting every kind.
- Restore validates the whole archive (decrypt, authenticate, parse, count) before touching anything, then stores a `pre-restore` safety backup of the current state, then replaces every collection (collections not in the backup are emptied) except `backup_config`, which keeps the current passphrase and schedule. The archive's files are written back to the bucket first (an archive with files is refused on a server without a bucket). Afterwards it re-runs `EnsureIndexes`, removes cached files with no restored record from `UPLOAD_DIR` (`pruneUploadCache`) and moves any bytes restored inside records (a backup from before the bucket) into the bucket. While `backup.RestoreInProgress()` is true the publishing scheduler, growth jobs, convention auto-poster and agent scheduler skip their run. Logins are those of the backup, so the admin is asked to log in again. The restore also cancels agent runs in progress first and afterwards closes the runs the backup had marked running (`recoverInterrupted`), so no agent stays stuck as running, and drops the cached OAuth signing key so ID tokens are signed with the restored one.
- Coverage is generic: every collection is dumped (`ListCollectionNames`) and every upload record stored in the bucket brings its file, so new content is backed up without changes here as long as its documents live in MongoDB and its files go through `uploadstore`. Keep it that way: never store data on local disk or under another bucket prefix, and give anything that caches database state in memory a reset after a restore.

### Authorization model
Three roles with distinct Gin context keys:
- **Global admin** (`isAdmin=true`) — full access to `/api/admin/*`
- **Team admin** (`isTeamAdmin=true` + `teamId` set) — access to `/api/team/*`; can manage their own team's accounts and members
- **Regular user** — access to `/api/posts`, `/api/footers`, `/api/watermarks`, `/api/inbox`

Posts and footers are scoped: if the user has a `teamId`, queries filter by team; otherwise by `userId`.

### Unified token authentication
A single bearer token (`sm_...` prefix for users, `st_...` for teams) authenticates all external access: REST API calls (`/api/*`) and MCP requests (`/api/mcp`). OAuth-connected MCP clients use their own tokens instead (see MCP server above), which work for `/api/mcp` only. Tokens are generated on the Profile page and passed as `Authorization: Bearer <token>`. Regenerating a token invalidates the previous one everywhere.

### Chrome extension (`chrome-extension/`)
A Manifest V3 Chrome extension that captures the current browser tab (screenshot + extracted page images) and sends the data to a SocialPod server's `/api/capture` endpoint to create a draft. Supports news and post draft types — episode drafts are created in the web UI only. Users configure their SocialPod server URL and API token in the extension popup. `make chrome-extension` produces a `socialpod-capture.zip` ready for Chrome Web Store upload.

Game titles in captured text always appear in plain double quotes (`"Wingspan"`) — house style across all published material. `gameNameQuotingRule` is appended to every capture system prompt, the team's `agentSystemPrompt` override included (`buildSystemPrompt`). For a BGG capture the exact title is known, so `enforceQuotedGameName` additionally quotes it in the generated text: it normalises typographic quotes, skips mentions inside a longer word or a URL, and is idempotent. Two fields are deliberately exempt: `gameNamePublisher` (a structured field the Episode form fills as `Name (Publisher)`) and a `newsTagline` that would exceed its 30-character chapter-title limit with the quotes added.

Captured images are normally narrowed down by a vision model (`selectBestImage`), but BoardGameGeek links bypass that entirely: a BGG game URL (`bggGameIDFromURL`) takes the cover from the BGG XML API — or, if that API is unavailable, from the game page's `og:image` — and runs it through `BGGHandler.downloadAndProcess`, the same letterbox + overlay pipeline as the UI's "import from BGG" button. The overlay matches what the corresponding form would use (`bggOverlayType`): the team's BGG watermark for news and post captures, the news episode overlay for episode captures. A BGG capture never falls back to the vision model for its image; if no cover can be fetched, the draft is created without one.

### n8n integration (`n8n-nodes-socialpod/`)
A pre-built n8n community node with a `dist/` directory already compiled. Install with `npm install --omit=dev` on the target machine — full `npm install` fails on Node < 22 due to the `isolated-vm` transitive dev dependency.

Supported resources: Post (create/get/list/update/delete/reschedule/retry), Footer (CRUD), Account (list), Mention (CRUD + export/import), Watermark (list/delete), AI Text (generate). All seven platforms are supported: Bluesky, Instagram, Twitter/X, Mastodon, Threads, LinkedIn, YouTube.

## Environment
Copy `.env.example` to `.env` and set at minimum `JWT_SECRET` (strong random string) and `MONGO_PASSWORD` before exposing the service. `APP_URL` must be publicly reachable for Instagram OAuth and webhooks to work.
